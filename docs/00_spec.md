# coin-collector — спецификация

## Идея

Парсер — отдельная самостоятельная сущность, которой не нужна перепроверка.
Он целиком отвечает за: сбор данных, форматирование фото, связывание с
источником цен, запись в базу и хранилище. Мы вылизываем его на сериях
украинского каталога до состояния полного доверия, после чего этот же код —
без переделок — встраивается в прод в двух тонких режимах: обновление
каталога (раз в неделю) и обновление цен (раз в сутки). Старый парсерный
слой основного репозитория (ukraine_recon, ukraine_pipeline) после этого
выпиливается.

Период вылизывания = гоняем парсер по сериям, смотрим результат на сайте,
фиксим, гоняем снова. Ревью-инструменты — временные строительные леса,
в продукт не входят.

## Принципы

1. **Один код на все режимы.** Прод вызывает ровно тот же код, что
   вылизывался на сериях. Никакой отдельной "продовой версии".
2. **Сначала сырьё, потом разбор.** Ответы источников сохраняются на диск.
   Правка парсера = переразбор локального снимка, без нового похода на сайт.
3. **Идемпотентность вместо dry-run.** Ключ записи — id карточки эмитента
   (`nbu:<id>`). Любой прогон можно повторить: повтор обновляет, не дублирует.
   Личные позиции пользователей (collection_items) парсер не трогает никогда —
   это единственный жёсткий запрет.
4. **Самоотчёт и стоп на аномалии.** После прогона — краткий отчёт (сколько
   карточек, сматчено, фото, аномалий). Сомнительные данные не пишутся молча:
   аномалия останавливает запись этой записи и попадает в отчёт.
   Примеры аномалий: цена изменилась в N раз (легаси-правило валидации из
   основной репы), не нашлось фото аверса/реверса, не сматчилась ссылка цены,
   карточка исчезла из выдачи источника (удаление — только руками).
5. **Ядро общее, страны — адаптеры.** В ядро попадает только доказанно общее.
   Специфика («монеты только в упаковке», гомоглифы НБУ) живёт в адаптере
   страны. Перевод названий — будущий модуль ядра, появится со страной без
   английской локали (Польша); в канонической записи поля локалей есть уже
   сейчас.

## Структура

```
coin-collector/
  core/
    schema.py        # каноническая форма записи монеты
    staging.py       # локальный кэш сырья и разобранных данных
    media.py         # выбор чистых аверс/реверс, webp 300/600/1200, ключи MinIO
    writer.py        # запись: postgres (ssh-туннель или локально на серваке) + MinIO
    report.py        # самоотчёт прогона, список аномалий
  countries/
    ua/
      nbu.py         # серии, карточки (POST по 100), обе локали uk/en
      ua_coins.py    # страницы монет, цены
      normalize.py   # кавычки, суффиксы металла, гомоглифы
      matcher.py     # НБУ <-> ua-coins: название+год+номинал
  staging/           # локальный кэш (в .gitignore)
    ua/<serie-slug>/
      raw/           # сырые ответы
      parsed/        # канонические записи, цены
      media/         # готовые webp
```

## Каноническая запись монеты

```json
{
  "source_id": "nbu:1234",
  "titles": {"uk": "Різдво Христове", "en": "Nativity of Christ"},
  "series": "2000-ліття Різдва Христового",
  "year": 1999,
  "denomination": {"value": 10, "unit": "грн"},
  "material": "срібло",
  "mintage": {"announced": 50000, "actual": null},
  "item_type": "coin",
  "subtype": null,
  "description": {"uk": "…", "en": "…"},
  "images": {"obverse": "media/1234/obverse_1200.webp",
             "reverse": "media/1234/reverse_1200.webp"},
  "price_source": {"source": "UA-Coins",
                   "url": "https://www.ua-coins.info/ua/list/…"}
}
```

Поля сверяются с колонками catalog_items на первой серии и фиксируются.

## Режимы запуска

```
run --country ua --serie <slug>     # полный прогон одной серии
run --country ua --all              # полный прогон страны
run --country ua --update-catalog   # новинки: первая страница НБУ vs база (прод, раз в неделю)
run --country ua --update-prices    # цены по сохранённым ссылкам ua-coins (прод, раз в сутки)
```

Все четыре — один и тот же конвейер: собрать -> обогатить -> фото -> записать.
Update-режимы просто сужают вход (новые карточки / только цены).

### Отчёт о прогоне

Прогон по расписанию отчитывается в API coin_keeper (`collector/core/job_report.py`):
`POST /internal/job-runs` перед работой, `PATCH` с исходом после. Там прогон
записывается в `job_runs` и уходит в админский телеграм — подробности и решения
в `docs/13-admin.md` основной репы.

Три правила, из которых состоит модуль:

- **Отчёт никогда не меняет исход прогона.** Недоступный, медленный или отвечающий
  ерундой API стоит строчки в логе — и только. Строка самоотчёта всё равно попадает
  в лог-файл, цены к этому моменту уже в базе.
- **Прогон открывается до работы.** Контейнер, убитый на середине, о своей смерти
  сообщить не может; открытая запись — единственный след такого случая.
- **Не удалось открыть — отправляем целиком в конце.** API мог лежать в 03:15 и
  подняться к 03:23; отчёт не должен пропадать из-за того, что не к чему прицепиться.

Без `JOB_REPORT_URL` и `JOB_REPORT_TOKEN` модуль не делает ничего: репетиция на
рабочей машине не должна появляться в боевой админке.

## Правила данных (Украина)

- Локали uk и en — официальные, с двух версий каталога НБУ. Русской нет и
  не будет, пока не решим иначе.
- Джерело-ссылка на карточке сайта — страница монеты на ua-coins.
- Атрибуция НБУ (данные и фото) — обязательная строка на сайте (useterms НБУ).
- Цены — только UA-Coins. Старые uCoin-снапшоты остаются историей, новые
  не создаются. uCoin из приоритетов и очередей убирается.
- Фото — чистые аверс/реверс (не тубы и не упаковки), исходник НБУ 1600px,
  на выходе webp 300/600/1200 с ключами по схеме MinIO основной репы.

## Пилот

Серия «2000-ліття Різдва Христового»: по ua-coins в ней 6 монет
(2 недрагметалл, 4 драгметалл), на сайте сейчас 4, у 50 грн битая цена
из uCoin (97,13 ₴). Цикл: прогон парсера -> смотрим на сайте -> фиксим ->
прогон. Дамп текущего состояния БД (dump_series.sql) — разовая точка
отсчёта перед первым прогоном, чтобы решить судьбу существующих записей
и увидеть привязанные личные позиции.

## Путь в прод

1. Вылизать на пилотной серии, пройти все серии страны.
2. Опубликовать coin-collector как зависимость (git-пакет).
3. В основной репе: два cron-джоба вызывают update-режимы; выпилить
   ukraine_recon и ukraine_pipeline; поменять приоритет источника
   «джерело» на ua-coins и снять uCoin.
4. Следующая страна = новый адаптер в countries/, руками по тому же циклу.

## Вне скоупа (пока)

- Перевод (модуль ядра, появится с Польшей).
- AI-маппинг братовой коллекции на новый каталог (отдельная задача после
  костяка).
- Автоудаление записей (никогда: исчезновение карточки у источника — только
  сигнал в отчёте).
