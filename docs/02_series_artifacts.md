# Что остаётся на диске после сбора одной серии

Справочник по всем артефактам сбора: где лежат, что внутри, какие
инварианты гарантированы, а какие — нет. Написан как вход для разговора
о заливке в БД, поэтому по каждому файлу отдельно отмечено, что из него
идёт в coin_keeper, а что остаётся служебным.

Состояние на 2026-09-09. Формат считается устоявшимся — дальше собираем
серию за серией, чиним неточности, и после каждой заливаем.

---

## 1. Карта каталогов

Две разные вещи по времени жизни: **коммитится** то, что описывает
каталог в целом, **не коммитится** (`.gitignore`, строка `/staging/`) —
всё, что скачано.

```
collector/countries/ua/
    series.json      ← справочник официальных серий НБУ, КОММИТИТСЯ
    db_map.json      ← slug серии → id в coin_keeper.coin_series, КОММИТИТСЯ

staging/ua/<slug-серии>/            ← всё, что собрано по одной серии
    raw/
        _meta.json                  когда качали и под каким именем серии
        uk_p1.html, uk_p2.html…     страницы поиска bank.gov.ua, украинские
        en_p1.html…                 они же, английские
    parsed/
        cards.json                  ГЛАВНЫЙ файл: канонические карточки монет
        anomalies.json              карточки, выброшенные парсером
        unmatched.json              карточки без пары на ua-coins
        photos.json                 итог обработки фото: кто победил и почему
    media/
        src/nbu_1560/               скачанные кандидаты + meta.json
        out/nbu_1560/               готовые WebP: obverse_300/600/1200 и т.д.

staging/ua/_ua_coins/               ОБЩЕЕ для всех серий, не per-series
    raw/1999.html, 2000.html…       годовые страницы каталога ua-coins
    pages/nbu_161.html              страница монеты на ua-coins
    prices/nbu_161.json             история цен, ответ сервера байт в байт
    prices/nbu_161.meta.json        откуда взята, контрольная точка, статистика
```

Порядок шагов, которым это наполняется:

```
--step series          → series.json                (один раз на весь каталог)
--step fetch           → raw/
--step parse           → parsed/cards.json, anomalies.json
--step match           → дописывает ua_coins в cards.json, пишет unmatched.json
--step fetch-photos    → media/src/
--step process-photos  → media/out/, parsed/photos.json
--step fetch-prices    → _ua_coins/pages/, _ua_coins/prices/
```

`--step all` = fetch, parse, match, fetch-photos, process-photos.
`fetch-prices` в `all` не входит намеренно: он бьёт по сети отдельно.

Порядок обязателен слева направо — каждый шаг читает то, что записал
предыдущий. Единственное исключение: повторный `parse` не затирает уже
проставленный `ua_coins` (перенос по `source_id`), так что перепарсить
серию после матчинга безопасно.

Размеры для ориентира: «Безсмертна моя Україно», 16 монет — 119 МБ, из
них подавляющая часть `media/src` (оригиналы НБУ по 2 МБ). `media/out`
и весь JSON — единицы мегабайт.

## 2. Сквозной ключ: `source_id`

Единственный идентификатор, который проходит через всё:

```
"nbu:1560"
```

- в `cards.json` — поле `source_id`;
- в именах каталогов и файлов — `nbu_1560` (двоеточие непортабельно в
  именах файлов);
- в coin_keeper — `catalog_items.source_key = 'nbu:1560'`.

Число после `nbu:` — id карточки на bank.gov.ua, он же в URL монеты у
НБУ. Это наш ключ, а не чужой: id ua-coins живёт **только** внутри блока
`ua_coins` карточки и в метах цен, и никогда не служит именем файла —
он выглядит как год и путает (`43` и `1998` — обе монеты 1999–2000 гг.).

**Важно для заливки.** `catalog_items.source_key` уникален не глобально,
а двумя частичными индексами: по `source_key` при `created_by IS NULL`
(общий каталог) и по паре `(created_by, source_key)` при
`created_by IS NOT NULL` (личные копии коллекционеров). Любой поиск
монеты по `source_key` обязан нести `AND created_by IS NULL`.

## 3. `series.json` — справочник серий (коммитится)

```json
{
  "country": "ua",
  "original_lang": "uk",
  "generated_at": "2026-09-08T14:29:23.640183+00:00",
  "series": [
    {
      "is_official": true,
      "names": { "uk": "2000-ліття Різдва Христового", "en": "2000 Years of Christmas" },
      "nbu_card_count": 6,
      "year_range": [1999, 2000],
      "slug": "2000-littia-rizdva-khrystovoho"
    }
  ]
}
```

37 записей. `slug` — имя каталога в `staging/ua/`. `names.uk` хранится
**байт в байт** так, как его хочет фильтр `serie[]` у НБУ, включая
хвостовой пробел и нестандартные апострофы, — это протокольная деталь, а
не человеческое имя (при заливке в `coin_series` она обрезается).
`nbu_card_count` — сколько карточек НБУ отдаёт по этой серии; расхождение
с фактическим `fetch` означает, что справочник устарел.

`db_map.json` — плоская таблица `slug → id` в `coin_keeper.coin_series`,
заполняется шагом `load-series` и коммитится. Соответствие серий —
ручное и проверенное, никогда не по совпадению имён.

## 4. `parsed/cards.json` — главный файл

Корень:

```json
{
  "series": { "uk": "Безсмертна моя Україно", "en": "My Immortal Ukraine " },
  "original_lang": "uk",
  "fetched_at": "2026-09-09T06:19:18.834991+00:00",
  "cards": [ … ]
}
```

`original_lang` — константа адаптера: для Украины всегда `"uk"`, то есть
украинский текст авторитетный, английский — перевод НБУ.

### Одна карточка

```json
{
  "source_id": "nbu:1560",

  "titles":    { "uk": "В єдності - сила", "en": "In Unity, Strength" },
  "title_raw": { "uk": "В єдності - сила (н)", "en": "In Unity, Strength" },
  "metal_suffix": "н",

  "denomination": { "value": 5, "unit": "hryvnia" },
  "circulation_date": "2022-07-11",
  "year": 2022,

  "material": "nickel_silver",   "material_raw": "нейзильбер",
  "quality":  "special_uncirculated", "quality_raw": "спеціальний анциркулейтед",
  "edge":     "reeded",          "edge_raw": "рифлений",

  "mintage": { "announced": 175000, "actual": 0 },
  "weight_grams": 16.54,
  "fine_weight_grams": null,
  "diameter_mm": 35.0,

  "description": {
    "uk": { "general": "…", "obverse": "…", "reverse": "…" },
    "en": { "general": "…", "obverse": "…", "reverse": "…" }
  },
  "artists": {
    "designers": [ { "uk": "дизайн монети: Малюта Аліна", "en": "Alina Maliuta" } ],
    "sculptors": [ { "uk": "програмне моделювання - Лук`янов Юрій", "en": "…" } ]
  },

  "images": {
    "obverse_url":     "https://bank.gov.ua/media/coins/1560/avers.jpg?v=19",
    "reverse_url":     "https://bank.gov.ua/media/coins/1560/revers.jpg?v=19",
    "obverse_big_url": "https://bank.gov.ua/files/coins_images/B87a.png?v=19",
    "reverse_big_url": "https://bank.gov.ua/files/coins_images/B87r.png?v=19"
  },

  "ua_coins": {
    "id": 2408,
    "url": "https://www.ua-coins.info/ua/list/2408-v-yednosti---syla",
    "matched_by": "exact",
    "year_used": 2022,
    "matched_at": "2026-09-09T06:19:46.286907+00:00"
  }
}
```

### Правила, которые держит парсер

**Пара «код + сырое значение».** Везде, где есть закрытый словарь,
рядом лежат оба: `material`/`material_raw`, `quality`/`quality_raw`,
`edge`/`edge_raw`. Код — наш, сырое — буквальный текст НБУ. Если сырое
значение не нашлось ни в одном списке `vocab.py`, карточка **не
угадывается**, а целиком уходит в `anomalies.json`. Значит, в
`cards.json` кодовые поля либо валидны, либо отсутствуют вместе с
карточкой.

Действующие домены (`collector/countries/ua/vocab.py`):

| поле | значения |
|---|---|
| `material` | `gold`, `silver`, `nickel_silver`, `bimetallic` |
| `quality` | `proof`, `uncirculated`, `special_uncirculated` |
| `edge` | `plain`, `reeded`, `plain_incuse_lettering`, `sector_reeded` |
| `denomination.unit` | `hryvnia`, `karbovanets` |

`uncirculated` собирает два разных сырых написания НБУ — «звичайна» и
«анциркулейтед»; это одно и то же качество, не опечатка.

**`titles` против `title_raw`.** `title_raw` — как напечатано у НБУ, с
хвостом вида `(н)`, `(зол)`; `metal_suffix` — этот хвост отдельно;
`titles` — очищенное имя. В БД идёт `titles`.

**Хвост про упаковку — часть имени, а не уточнение.** «В єдності - сила»
и «В єдності - сила у сувенірній упаковці» — **две разные монеты** с
разными `source_id`, а не одна с примечанием. Так их видит и НБУ, и
ua-coins. Схлопывать их при заливке нельзя.

**`year` против `circulation_date`.** `circulation_date` — дата ввода в
обращение (ISO), `year` — год из неё. Год на самой монете может
отличаться на единицу, поэтому матчинг с ua-coins и допускает сдвиг
`year_shift`.

**`mintage.actual: 0`** — это буквально то, что напечатал НБУ, а не
«неизвестно». Отсутствие данных всегда `null`, не `0`.

**Что бывает `null`:** `weight_grams`, `fine_weight_grams`,
`diameter_mm`, любая половина `titles`/`description`/`artists`
(английской версии у части старых монет просто нет), `ua_coins`.

**`ua_coins`.** `null` означает «пары не нашли» — причина лежит в
`unmatched.json`. `matched_by` — `exact` или `year_shift`. Матчинг
детерминированный: ключ `(нормализованное имя, год, номинал)`, никакого
фаззи-сравнения; неоднозначность — это конфликт в отчёте, а не тихий
выбор одного из вариантов.

### Что из карточки идёт в coin_keeper

Соответствие полям `catalog_items` сверялось на пилотной серии.
`descriptions` и `artists` в БД — JSONB, форма внутри та же, что здесь.
`images` в БД **не идут** — туда идут обработанные файлы из `media/out`
(см. §6). `title_raw`, `metal_suffix`, все `*_raw` — служебные, нужны
для разбора и для восстановления доверия к парсингу; хранить их в БД
смысла нет, кроме, может быть, `*_raw` как страховки.

## 5. `anomalies.json` и `unmatched.json`

Оба — списки; пустой список `[]` означает «всё чисто».

**`anomalies.json`** — карточки, которые парсер отказался собрать. Такой
монеты в `cards.json` НЕТ вообще.

```json
[ { "source_id": "nbu:88", "field": "quality",
    "raw_value": "новое написание",
    "message": "unknown quality value" } ]
```

Правило: непонятое значение никогда не угадывается и не пишется как
`null` — карточка выбывает целиком. Чинится это дописыванием одной
строки в `vocab.py` и повторным `parse`.

**`unmatched.json`** — карточки без пары на ua-coins. Они в `cards.json`
есть, у них `ua_coins: null`.

```json
[ { "source_id": "nbu:1591", "title": "…", "year": 2023, "denomination": 5,
    "reason": "conflict: more than one ua-coins candidate",
    "candidates": [ { "id": 2441, "url": "…", "title": "…", "year": 2023 } ] } ]
```

Варианты `reason`: нет кандидата вообще (`candidates_seen` — что рядом
лежало), конфликт из нескольких кандидатов (`candidates`), и конфликт
«одну строку ua-coins забрали две карточки» (`conflict_with`).

Практическое следствие: **у такой монеты не будет истории цен**, потому
что цены качаются только по `ua_coins.id`. Сама монета при этом
полноценная и заливается.

## 6. Фотографии

### `media/src/nbu_1560/` — что скачали

Все кандидаты как есть плюс `meta.json`:

```json
{
  "source_id": "nbu:1561",
  "fetched_at": "2026-09-09T06:21:46.709966+00:00",
  "candidates": [
    { "file": "nbu_obverse.jpg", "url": "…", "alt": null, "source": "nbu",
      "width": 880, "height": 1600, "bytes": 532355 },
    { "file": "uacoins_01.webp", "url": "…",
      "alt": "Аверс В єдності - сила у сувенірній упаковці",
      "source": "ua_coins", "width": 880, "height": 1600, "bytes": 253946 }
  ]
}
```

До четырёх файлов от НБУ (миниатюра и полноразмерный оригинал на каждую
сторону) плюс вся галерея ua-coins. `width`/`height` — реальные размеры
скачанного файла, а не то, что обещала папка на сайте: у ua-coins
«big» бывает мельче «middle».

### `media/out/nbu_1560/` — что отдаём

```
obverse_300.webp  obverse_600.webp  obverse_1200.webp
reverse_300.webp  reverse_600.webp  reverse_1200.webp
```

Числа — **ярлыки тира**, а не гарантия размера: файл пишется в том
разрешении, которое реально есть у источника, но не выше ярлыка.
Источник на 1120 px уезжает в `obverse_1200.webp` как 1120 px, а не
проваливается в тир 600. Тир пропускается, если он даёт менее 3 %
прироста, — поэтому маленький оригинал не будет записан трижды.

### `parsed/photos.json` — почему получилось именно так

```json
{ "cards": [ {
  "source_id": "nbu:1561",
  "roles": {
    "obverse": {
      "winner": { "source": "ua_coins", "src_file": "uacoins_03.webp",
                  "width": 1600, "height": 1600,
                  "processing": "already_transparent",
                  "is_coin": true, "shape_reason": "ok" },
      "files": [ { "file": "obverse_300.webp", "width": 300, "height": 300 } ],
      "low_res": false,
      "outline_dip": 0.0
    },
    "reverse": { … }
  },
  "rejected": [ { "src_file": "uacoins_01.webp", "reason": "cut damaged the shape" } ],
  "anomalies": [],
  "pair_silhouette_iou": 0.997
} ] }
```

- `processing` — `already_transparent` (у источника уже был альфа-канал),
  `cut` (фон вырезали) или `kept_bg` (фон оставили как есть).
- `pair_silhouette_iou` — насколько сошлись силуэты аверса и реверса.
  Ниже 0.93 → аномалия: одну из сторон, скорее всего, вырезали криво.
  Это единственная проверка, которая не предполагает никакой формы
  монеты (половинка сердца и разрезанный пополам круг геометрически
  неразличимы).
- `low_res` — короткая сторона **исходной** фотографии меньше 600 px.
  Считается по источнику, а не по результату, специально: вырезание фона
  подрезает картинку до альфа-рамки, и снимок 600×600, вышедший 600×598,
  иначе получал бы клеймо low-res из-за двух пикселей поля.
- `outline_dip` — насколько контур просел внутрь собственной радиальной
  огибающей, то есть след эрозии края при вырезании. `null` для
  некруглых монет (писанка, половина сердца): там та же цифра мерила бы
  форму, а не дефект.
- `rejected` — кандидаты, выбывшие с причиной. Их файлы остаются в
  `media/src`.
- `anomalies` — строки вида `no usable photo for reverse`. Пустой список
  = карточка полная.

Готовность серии по фото читается так: у каждой карточки обе роли
заполнены, `anomalies` пуст, `pair_silhouette_iou` выше порога.

Содержимое `media/out` едет в бакет как есть, каталогами: `mc mirror`
кладёт `nbu_1560/obverse_600.webp` под ключ
`catalog-src/nbu_1560/obverse_600.webp`, и именно этот ключ шаг
`load-cards` пишет в `media_files.storage_key`. Ключ намеренно НЕ несёт
`catalog_item_id` (в отличие от `catalog/{id}/{role}/…` в самом
coin_keeper): файлы уезжают в бакет ДО того, как строки появятся в БД, а
у усыновлённой легаси-записи id вообще не предсказать с этой стороны.

## 7. История цен

Общая на все серии: цена — свойство монеты, а не серии, поэтому каталог
один, `staging/ua/_ua_coins/prices/`, а имена — по НБУ.

### `prices/nbu_161.json`

Ответ подписанного эндпоинта ua-coins **байт в байт**, без переупаковки:

```json
[ { "date": "2016-07-18", "price": 143 },
  { "date": "2016-07-19", "price": 143 },
  { "date": "2026-09-09", "price": 568 } ]
```

Плоский массив, поденно, гривны. Что про эти данные известно точно:

- **пропуски дат — норма.** Пропущенный день, пропущенные три недели.
  Проверки непрерывности нет и не будет: пропуск означает «не торговали»,
  а не «данные битые».
- **одиночные выбросы — норма.** 520 → 650 → 520 на этом рынке реальная
  сделка. Никакой разметки `is_suspect`, никакого сглаживания. Решение
  принято явно.
- **даты строго возрастают.** Это единственное свойство, нарушение
  которого означает, что файл не тот, чем мы его считаем. Оно вместе с
  непарсящейся датой и неположительной/нечисловой ценой выбрасывает
  **монету целиком**: половина истории хуже, чем её отсутствие.

Объёмы: 232–3524 точки на монету, ~15.9 тыс. точек на 6 монет пилотной
серии. По стране это сотни тысяч строк — построчный INSERT через туннель
не вариант, только COPY пачками.

### `prices/nbu_161.meta.json`

```json
{
  "ua_coins_id": 43,
  "source_id": "nbu:161",
  "fetched_at": "2026-09-09T07:24:18.875859+00:00",
  "page_url": "https://www.ua-coins.info/ua/list/43-rizdvo-khrystove",
  "prices_url_used": "/coin/prices/43?_hash=…&expires=1788939555",
  "points": 3522,
  "date_min": "2016-07-18", "date_max": "2026-09-09",
  "price_min": "143", "price_max": "1102",
  "series_error": null,
  "current_price": { "price": "568", "date": "2026-09-09",
                     "found_by": "price-note", "text": "Орієнтовна ринкова ціна станом на…" },
  "current_price_check": "ok",
  "current_price_candidates": [ … ],
  "nbu_issue_price": null
}
```

`current_price_check` — контрольная точка: цена, которую страница
печатает словами, обязана совпасть с последней точкой графика. `ok` /
`mismatch` / `not_found`. Расхождение — предупреждение, не ошибка:
грузим мы график, страница только сверяет.

`nbu_issue_price` — не рыночная цена, а официальная цена НБУ, которую
ua-coins печатает вместо графика, пока у совсем новой монеты ещё нет
подтверждённых продаж (виджет `market-pending`). `null`, пока у монеты
есть настоящая история (что для подавляющего большинства карточек и
есть весь смысл этого поля). У совсем новой монеты страница даже не
содержит ссылки на chart-эндпоинт — `_fetch_one` в этом случае не
бросает `RuntimeError`, а пишет `prices.json` как `[]` и
`prices_url_used: null`, если на странице нашёлся `market-pending`;
`load-prices` подхватывает это поле сам (`read_nbu_issue_price()`) и,
когда график пуст, пишет **одну** синтетическую точку с
`source='NBU-issue'`, а не `'UA-Coins'` — это цена эмитента, не
рыночная котировка, и смешивать её с обычной историей означало бы
выдать одно за другое. Подробности и почему это не часть ночного
`update-prices` — `docs/01_findings.md`, «Официальная цена НБУ на
странице новой монеты — не рыночная котировка».

`prices_url_used` — след для разбора полётов и **больше ничего**.
Подписанный URL живёт около двух суток, поэтому в БД как `source_url`
идёт `page_url`, страница монеты.

`ua_coins_id` в мете — то, ради чего файлы названы по НБУ: при попадании
в кэш он сверяется с текущим матчем, и если карточку перематчили на
другую строку ua-coins, история перекачивается вместо того, чтобы тихо
лежать рядом устаревшей.

### `pages/nbu_161.html`

Страница монеты на ua-coins целиком. Не кэш — с неё каждый раз читается
свежая подпись. Лежит, чтобы было на что смотреть, когда сайт поменяет
разметку, и чтобы контрольную точку можно было пересчитать без сети.

## 8. Что про заливку уже выяснено

Три вещи, которые упрутся в схему coin_keeper независимо от того, какую
форму примет загрузчик.

**1. `ON CONFLICT` на снапшотах цен идемпотентности не даёт.**
`uq_market_price_snapshots_item_source_grade_observed` — обычный
`UNIQUE (catalog_item_id, source, grade, observed_at)`. Все наши строки
идут с `grade = NULL` (ua-coins котирует одну цену без градации), а
Postgres по умолчанию считает NULL отличным от любого NULL — то есть две
одинаковые наши строки не конфликтуют, и повторный прогон вставил бы всю
историю второй раз. Дедупликация делается на стороне вставки:
`WHERE NOT EXISTS (… AND m.grade IS NOT DISTINCT FROM t.grade …)` плюс
`DISTINCT ON` внутри пачки. Правильное решение — `NULLS NOT DISTINCT` в
схеме coin_keeper, но это её зона.

**2. `source_key` уникален на пользователя** (см. §2) — поиск монеты
обязан нести `AND created_by IS NULL`.

**3. `observed_at` — полночь UTC** от даты точки. Дата у нас
календарная, констрейнт ключуется на точный timestamp; любая другая
привязка сделает повторный прогон новыми строками.

Ещё из практики: `currency_code` — внешний ключ на `currencies.code`,
так что `UAH` должна там быть, иначе транзакция упадёт на FK. И границу
скоупа стоит держать явной: **цены грузятся только тем монетам, которые
уже есть в `catalog_items`**. Монета без строки в БД — это не ошибка
заливки цен, это «сначала залей монету».

Что к этому добавил шаг `load-cards` (подробности в
`docs/01_findings.md`):

**4. Ключ файла в бакете не может нести `catalog_item_id`.** Файлы
уезжают в бакет до строк, а у усыновляемой легаси-записи id
непредсказуем. Ключ идёт по НБУ-идентификатору:
`catalog-src/nbu_88/obverse_600.webp`.

**5. `collection_group` — `NOT NULL` без дефолта.** «Загрузчик не
классифицирует монеты» поэтому означает «пишет один раз при создании
строки и больше никогда»: `commemorative`, как ставит собственный
НБУ-создатель записей в coin_keeper.

**6. Усыновление старой записи — только через `price_source_links`**
(`source='NBU'`), никогда по названию/году/номиналу. id строки
сохраняется, меняется только `source_key`.

**7. Типы: float из JSON никогда не равен `Decimal` из `numeric`.**
Дифф «что изменилось» сравнивает значения уже в типах БД, иначе каждый
повторный прогон переписывал бы строку тем же самым значением.

## 9. Чего в артефактах нет — намеренно

- **Никакой разметки «подозрительных» цен.** Рынок тонкий, выбросы
  легитимны.
- **Никакой конвертации валют** и никакого пересчёта стоимости
  коллекций.
- **Никакого фаззи-сопоставления** нигде: ни серий по именам, ни монет с
  ua-coins. Неоднозначность всегда попадает в отчёт, а не разрешается
  молча.
- **Никакого суточного апдейта цен.** История добирается одним разом;
  «догонять» её будет отдельный будущий шаг.
- **Схема БД не меняется** из этого репозитория.
